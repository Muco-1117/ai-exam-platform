# 运行与部署说明

以下命令以 PowerShell 为例，工作目录均为克隆后的仓库根目录。Linux/macOS 使用 `mvn` / `npm`，并用 `export` 设置对应环境变量。

## 1. 环境与端口

JDK 21、Maven 3.9、Node.js 24 LTS、MySQL 8 和 Redis。Redis 默认使用 6379、数据库 0；主业务服务持有数据库与 Redis 连接，AI / 判题服务不直接访问业务库。

| 进程 | 默认端口 | 健康检查 |
| --- | ---: | --- |
| 网关 | 8080 | `GET /health` |
| 主业务 | 8081 | `GET /health` |
| 判题 | 8082 | `GET /health` |
| AI | 8083 | `GET /health` |
| Vite 开发前端 | 5173 | 浏览器访问页面；端口冲突时以 Vite 输出为准 |

网关通过 `EXAM_URL` 代理主业务 `/api/` 和 `/ws/`；AI 与判题的 `/internal/` 接口由主业务调用，不由网关直接公开。

## 2. 初始化数据库

`sql/ai_exam.sql` 会**删除并重建 `ai_exam` 数据库**，适用于独立的新环境。已有同名数据库时先备份并检查脚本，不能直接当作升级脚本运行。

```powershell
cmd /c "mysql --default-character-set=utf8mb4 -u root -p < sql\ai_exam.sql"
```

初始化包含本机演示账号 `admin`、`student`，初始密码均为 `123456`。公开部署前应通过数据库管理流程更换密码 / 移除演示账号；当前接口未提供完整的自助改密流程。

## 3. 环境变量

| 变量 | 使用方 / 默认 | 说明 |
| --- | --- | --- |
| `DB_HOST` / `DB_PORT` / `DB_NAME` | backend；localhost / 3306 / ai_exam | MySQL 地址、端口与库名 |
| `DB_USER` / `DB_PASSWORD` | backend；root / 空 | 建议使用受限的应用账号 |
| `REDIS_HOST` | backend；localhost | Redis 默认端口 6379、数据库 0 |
| `JWT_SECRET` | backend；无默认密钥 | 必须设置至少 32 字节的私有随机值；缺失或过短时启动失败，重启保持一致 |
| `SERVICE_TOKEN` | 三个 Java 服务；测试占位值 | 三者必须相同，生产环境必须覆盖 |
| `JUDGE_URL` / `AI_URL` | backend；127.0.0.1:8082 / :8083 | 内部服务 HTTP 基址 |
| `GATEWAY_URL` | backend；http://127.0.0.1:8080 | 拓扑健康检查使用 |
| `PORT` | 各独立进程 | 覆盖该进程的默认端口；不要给所有服务设置同一 PORT |
| `EXAM_URL` | gateway；http://127.0.0.1:8081 | 网关的主业务上游 |
| `FRONTEND_DIST` | gateway；frontend/dist | 静态站点目录 |

Redis 需要额外端口 / 密码 / 隔离库时，可使用 Spring 标准变量 `SPRING_DATA_REDIS_PORT`、`SPRING_DATA_REDIS_PASSWORD`、`SPRING_DATA_REDIS_DATABASE`。

以下设置仅对当前终端及其子进程生效：

```powershell
$env:DB_HOST = 'localhost'
$env:DB_PORT = '3306'
$env:DB_NAME = 'ai_exam'
$env:DB_USER = '<database-user>'
$env:DB_PASSWORD = '<database-password>'
$env:JWT_SECRET = '<random-secret-of-at-least-32-bytes>'
$env:SERVICE_TOKEN = '<same-random-token-in-all-three-java-terminals>'
```

在每个 Java 服务终端设置一致的 `SERVICE_TOKEN`；数据库和 JWT 变量仅需在主业务终端设置。环境变量不会自动从一个已打开的终端传到另一个终端。

## 4. 开发启动

先启动 MySQL、Redis 并初始化数据库。三个 Java 命令会一直占用终端，必须**分别运行**，不能粘贴为一条串行启动脚本。

终端一：

```powershell
mvn.cmd -pl services/judge-service spring-boot:run
```

终端二：

```powershell
mvn.cmd -pl services/ai-service spring-boot:run
```

终端三：

```powershell
mvn.cmd -pl backend spring-boot:run
```

终端四（网关只使用 Node.js 内置模块，无须安装 npm 依赖）：

```powershell
node .\gateway\server.mjs
```

终端五：

```powershell
npm.cmd --prefix frontend ci
npm.cmd --prefix frontend run dev
```

开发访问 `http://localhost:5173`。Vite 的 `/api`、`/ws` 固定代理到 `localhost:8080`；更换网关端口时同步调整 `frontend/vite.config.ts`。

确认四个 `/health` 端点可达后，使用两个演示角色分别检查登录、练习、考试和管理功能。健康检查不能替代数据库、Redis 和业务操作验证。

## 5. AI 演示与真实模型

SQL 的 `config` 表中包含 `ai.api.url`、`ai.api.model`、`ai.api.key`。当前未提供配置这些值的独立管理接口，请由数据库维护者在受控连接中修改；不要将真实 Key 放进初始化 SQL 或 Git。

- `ai.api.key` 为空：返回 `DEMO` 固定题目，便于本地验证链路。
- Key 非空：使用配置的完整 Chat Completions URL 和模型名调用外部服务，返回 `LIVE`。
- 主业务将待确认结果保存在 Redis 中，TTL 为 24 小时；确认入库后还需要题目审核。

默认 URL / 模型为 DeepSeek 示例配置，可改为兼容该请求与响应结构的服务。真实模型调用可能产生费用；当前验证未调用付费模型。

## 6. 构建与部署

```powershell
mvn.cmd -B clean verify
npm.cmd --prefix frontend ci
npm.cmd --prefix frontend run build
```

构建产物包括 `backend/target/ai-exam-backend-1.0.0.jar`、`services/ai-service/target/ai-service-2.0.0.jar`、`services/judge-service/target/judge-service-2.0.0.jar` 及 `frontend/dist/`。分别使用 `java -jar` 运行三个 JAR，再启动网关。正式页面由网关 8080 提供；通过 HTTPS 反向代理发布，转发 WebSocket Upgrade。

数据库、Redis、8081/8082/8083 应限制为内部访问。当前内部接口使用共享令牌；令牌的开发默认值只适合本机演示，JWT 必须自行设置私有随机密钥。生产上线仍需要结合网络、账号、备份和模型接口配置完成单独验收。

## 7. 排查

| 现象 | 检查 |
| --- | --- |
| 网关 502 | backend 是否启动，`EXAM_URL` 是否正确 |
| 网关页面 503 | 是否已生成 `frontend/dist`，`FRONTEND_DIST` 是否正确 |
| 内部服务 403 | 三个 Java 进程的 `SERVICE_TOKEN` 是否一致 |
| 登录时签名失败 | `JWT_SECRET` 是否至少 32 字节 |
| AI 确认结果失效 | Redis 是否可用、结果是否已确认或超过 24 小时 |
| 只能生成固定题目 | 检查 `config.ai.api.key` 是否为空；DEMO 是预期回退 |
| Vue 编译失败 | 使用 Node.js 24 LTS，并按锁文件执行 `npm ci` |
